# SplitOS — Problem and Goal Analysis

## 1. Problem statement

Современный игровой ПК часто одновременно используется как рабочая станция и игровое устройство.

Стандартная Windows 11 предоставляет универсальное окружение, но не разделяет рабочий и игровой пользовательские контексты достаточно глубоко.

В результате:

- игровые клиенты и службы могут оставаться активными во время работы;
- рабочие процессы могут продолжать работать во время игры;
- уведомления и фоновые процессы создают лишнюю нагрузку и шум;
- переключение монитора/TV, звука, power profile и устройств ввода выполняется вручную;
- Windows desktop UX плохо приспособлен для управления исключительно контроллером;
- пользователю приходится отдельно взаимодействовать с несколькими игровыми клиентами;
- настройки игр не адаптируются автоматически к текущему игровому дисплею и возможностям ПК;
- один компьютер не ощущается как два специализированных устройства, хотя технически выполняет обе роли.

---

## 2. Problem separated from solution

### Problem

> Пользователь не имеет управляемого и предсказуемого способа переключить один Windows-PC между рабочим и игровым контекстом так, чтобы каждый контекст использовал только необходимые процессы, устройства, приложения и UX.

### Not the problem

Проблемой сама по себе не является:

```text
"в Windows нет красивого игрового лаунчера"
"Windows использует слишком много RAM"
"Steam неудобный"
"нужна отдельная кнопка Game Mode"
```

Это возможные проявления или части решения.

---

## 3. Product goal

Создать управляемый дистрибутив на базе Windows 11, в котором пользователь после входа выбирает один из двух взаимоисключающих контекстов:

```text
WORK
xor
GAME
```

Каждый контекст должен:

- иметь собственный набор активных процессов и политик;
- использовать соответствующие устройства и профили;
- минимизировать ненужную активность другого контекста;
- предоставлять UX, соответствующий текущей задаче пользователя.

---

## 4. Work Mode goal

Work Mode должен в первой версии прежде всего предоставлять:

> чистую, предсказуемую и совместимую Windows-среду, сфокусированную на рабочих приложениях и процессах.

Расширенная кастомизация Work Mode является вторичной задачей.

В будущем возможны:

- workspace layouts;
- notes;
- application pinning;
- focus environments;
- desktop customization;
- дополнительные productivity-функции.

---

## 5. Game Mode goal

Game Mode является основным UX-фокусом первой версии.

Он должен:

- изолировать игровой контекст от ненужной рабочей активности;
- предоставить SplitOS Game Launcher;
- объединять игры из поддерживаемых внешних Game Clients;
- подготавливать дисплей, звук и input context;
- поддерживать Controller и Keyboard & Mouse profiles;
- применять game-specific profiles;
- адаптировать настройки игры к текущему hardware/display context;
- предоставлять Shared Apps через gaming-oriented представление;
- оставаться активным после завершения игры до ручного перехода в Work Mode.

---

## 6. Success signals

На концептуальном уровне проект считается движущимся к цели, если пользователь может:

1. загрузить SplitOS;
2. войти в пользовательский контекст;
3. выбрать Work или Game;
4. работать без фоновой активности ненужного игрового контекста;
5. перейти из Work в Game через безопасный pre-flight;
6. выбрать игру через единый Game Launcher;
7. запустить её с корректным display/input/game profile;
8. завершить игру и вернуться в Game Launcher;
9. использовать до трёх Shared Apps в игровом контексте;
10. вручную вернуться в Work Mode;
11. получать проверенные обновления SplitOS вместо неподтверждённых feature/system updates Windows.

---

## 7. Non-goals

SplitOS не ставит целью:

- создать собственное ядро ОС;
- заменить Windows kernel;
- переписать DirectX;
- обходить DRM;
- вмешиваться в anti-cheat;
- изменять matchmaking;
- изменять сетевой код игры;
- подменять игровой input ради преимущества;
- становиться владельцем магазинов и лицензий внешних Game Clients;
- заставлять пользователя использовать отдельные физические диски для разных режимов.
